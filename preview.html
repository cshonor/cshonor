Flagship Project

hft-embedded-linux-study  —  34 modules · 8,000+ notes · HFT low-latency + embedded Linux

递进主轴：硬件底层 → 编程语言 → Linux 系统 → 驱动/设备树 → 嵌入式工程 → 网络栈 → 性能工具 → HFT 上层业务

00–20 编号即学习顺序，.5 / .6 / .7 不是子模块，而是现代补丁层——经典书基于 2.6/3.x 内核，这些模块补齐 5.x/6.x 的真实实现（bootmem→memblock、SLAB→SLUB、LRU→MGLRU、page→folio）。

动手线 L0 → L5（项目本身就是路径，不是读完书再做）：

L0自实现 malloc + 对齐/合并 benchmark能解释 chunk header / bins / M_MMAP_THRESHOLD
L1多线程 TCP echo server（epoll ET + 线程池）p99 < 200μs，能画出请求完整路径
L2perf 定位并消除一次真实抖动火焰图 + perf stat 说清瓶颈归属
L3UDP 组播行情接收器（含丢包统计）10 万 pps 下零丢包，能说出丢在哪一层
L4SPSC 无锁 ring（padding 前后对比）单跳 < 100ns，p99 < 200ns，批量消费版更快
L5三进程 FeedHandler → Book → Strategy软件栈 tick-to-trade p99 < 10μs（自测环境如实记录）
调试与开发同权重：右列那些指标不是靠感觉判断的，只能靠工具测出来。三层顺序固定——先让它对（gdb/strace/ASan/KASAN），再让它快（perf/eBPF），最后让它可观测（bpftrace + BPF 工具谱系）。
ARM64 汇编在 L4 第一次变现：x86 是 TSO 强序，acquire/release 编译成零指令——「忘了写 memory_order」在 x86 上常常碰巧能跑；ARM64 弱序，ldar/stlr 少一条就直接崩。
